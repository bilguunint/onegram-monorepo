## Модуль 0 — Сэтгэлгээний өөрчлөлт: төвлөрсөн vs төвлөрөлгүй

Чи өдөр бүр **төвлөрсөн (centralized)** системтэй ажилладаг:
- Firestore = нэг эзэнтэй (Google + чи) өгөгдлийн сан
- Хэрэглэгч чамд итгэдэг: "OneGram миний 5гр алтыг зөв хадгалж байгаа"
- Чи дурын үед `balance.gold`-ийг өөрчилж чадна

**Blockchain = төвлөрөлгүй (decentralized).** Эзэн байхгүй. Дүрэм (код) ба
математик л захирна. Хэн ч (чи ч мөн) дүрмийг зөрчиж чадахгүй.

| | Төвлөрсөн (Firebase) | Төвлөрөлгүй (Blockchain) |
|---|---|---|
| Эзэн | Google + чи | Хэн ч биш / бүгд |
| Итгэл | "Тэдэнд итгэ" | "Кодыг шалга" |
| Унтрах эсэх | Сервер унтарч болно | Хэзээ ч зогсохгүй |
| Засвар | Admin засна | Түүх өөрчлөгдөшгүй |

**Гол ойлголт:** Blockchain нь "хурдан DB" биш. Удаан, үнэтэй. Гэхдээ
**итгэлгүйгээр (trustless) ажиллах** чадварыг өгдөг — энэ нь мөнгө, хөрөнгийн хувьд асар үнэ цэнтэй.

🔬 **Дасгал:** OneGram дээр итгэл шаардагддаг 3 цэгийг бич (жишээ: "хэрэглэгч
надад алтаа хадгалуулдаг"). Тэдгээрийн аль нь blockchain-аар "итгэлгүй" болж чадах вэ?

## Модуль 1 — Blockchain яг юу вэ?

**Тодорхойлолт:** Блок-уудаас тогтсон, криптографаар холбогдсон, олон
компьютер дээр хуулбарлагдсан, зөвхөн **нэмж л болдог (append-only)** дэвтэр.

Гурван багана дээр зогсоно:

### 1.1 Hash (хэш) — дижитал хурууны хээ
Hash функц нь дурын өгөгдлийг тогтмол урттай "хурууны хээ" болгоно. Жишээ:
`keccak256("OneGram") → 0x6f4a...` Өгөгдөл арайхан өөрчлөгдвөл хээ бүрэн өөрчлөгдөнө.

### 1.2 Блокийн гинж
Блок бүр өмнөх блокийнхоо hash-ийг агуулна:
```
Блок 1 [өгөгдөл | prevHash: 0000] → hash: A1
Блок 2 [өгөгдөл | prevHash: A1  ] → hash: B7
Блок 3 [өгөгдөл | prevHash: B7  ] → hash: C3
```
Блок 1-ийг засвал A1 өөрчлөгдөнө → Блок 2 эвдэрнэ → бүх гинж унана. **Иймээс түүх өөрчлөгдөшгүй.**

### 1.3 Консенсус
Олон зангилаа (node) ижил дэвтрийн хуулбартай. Шинэ блок нэмэхэд **олонх нь
зөвшөөрөх ёстой**. Нэг хүн худал бичиж чадахгүй. (Bitcoin = Proof-of-Work,
Ethereum/Polygon = Proof-of-Stake.)

🔗 **OneGram-той холбоос:** Бидний бичсэн `mint`/`burn` бүр нэг **transaction**
болж блокт орно. `amoy.polygonscan.com` дээр бүх блок, tx-ийг харж болно.

🔬 **Дасгал:** [scripts/testFlow.js](scripts/testFlow.js)-г уншаад, доторх mint →
transfer → burn тус бүр хэдэн transaction үүсгэхийг тоол.

## Модуль 2 — Wallet, түлхүүр, хаяг

Blockchain дээр нэвтрэх нэр/нууц үг **байхгүй**. Оронд нь түлхүүрийн хос:

- **Private key** — нууц тоо. Үүгээр гүйлгээнд гарын үсэг зурна. *Алдвал бүх хөрөнгөө алдана.*
- **Public key / Address** — private key-ээс гаргаж авдаг нийтийн хаяг (`0x1a2b...`). Энэ нь "дансны дугаар" шиг.
- **Seed phrase** — 12/24 үгийн жагсаалт. Үүнээс олон private key үүсгэдэг (HD wallet).

```
Seed phrase → Private key → Public key → Address (0x...)
   (нуу!)        (нуу!)        (нээлттэй)   (нээлттэй)
```

**Гарын үсэг (signing):** Гүйлгээ хийхдээ private key-ээрээ гарын үсэг зурна.
Сүлжээ public key-ээр шалгаад "тийм, энэ хаягийн эзэн зөвшөөрсөн" гэж батална —
private key-ийг хэзээ ч дамжуулахгүйгээр. Энэ бол криптографийн увидас.

🔗 **OneGram-той холбоос:** [walletService.js](../functions/src/blockchain/walletService.js)
нь нэг seed phrase-ээс хэрэглэгч бүрт хаяг үүсгэдэг (custodial). Хэрэглэгч
private key-ээ мэдэхгүй — чи (backend) хадгална. Энэ нь UX-ийг хялбар болгодог
ч итгэлийг чам руу буцаадаг (Модуль 9-д гүнзгийрүүлнэ).

🔬 **Дасгал:** Node дээр ажиллуул:
```js
const { ethers } = require("ethers");
const w = ethers.Wallet.createRandom();
console.log(w.address, w.privateKey, w.mnemonic.phrase);
```
Гурван өөр wallet үүсгэ. Address яагаад бүгд `0x`-ээр эхэлж 42 тэмдэгттэй вэ?

## Модуль 3 — Transaction ба Gas

**Transaction (tx):** Сүлжээний төлөвийг өөрчлөх дурын үйлдэл (мөнгө явуулах,
контракт дуудах). Tx бүр:
- `from` (хэн), `to` (хаашаа), `value`/`data` (юу), гарын үсэг
- **Gas** — тооцоолол хийсний "түлш". Сүлжээг ажиллуулагчдад төлдөг шимтгэл.

**Gas яагаад хэрэгтэй вэ?** Спам-аас хамгаална, зангилаануудыг урамшуулна.
Ethereum дээр үнэтэй ($1–50), Polygon дээр маш хямд (~$0.001).

**Чухал:** Унших (балансыг харах) **үнэгүй**. Бичих (mint, transfer) **gas-тай**.

🔗 **OneGram-той холбоос:** [testFlow.js](scripts/testFlow.js)-д Alice бэлэг явуулахын
өмнө бид түүнд бага зэрэг gas (test-POL) илгээдэг — учир нь `transfer` нь tx,
gas шаардана. `balanceOf` дуудахад gas хэрэггүй (унших).

🔬 **Дасгал:** Яагаад custodial загварт "backend gas төлнө" гэдэг нь хэрэглэгчийн
хувьд давуу тал болох вэ? (Сэжүүр: энгийн хэрэглэгч test-POL-ийг хаанаас олох вэ?)

## Модуль 4 — Сүлжээнүүд: Bitcoin, Ethereum, L2, testnet

- **Bitcoin** — анхны blockchain. Зөвхөн мөнгө дамжуулах. Smart contract бараг алга.
- **Ethereum** — програмчлагддаг blockchain. Smart contract эндээс эхэлсэн. Үнэтэй.
- **Layer 2 (L2)** — Ethereum дээр суурилсан хямд, хурдан сүлжээ. **Polygon** үүний нэг.
- **Mainnet vs Testnet:**
  - *Mainnet* — бодит мөнгө, бодит хөрөнгө.
  - *Testnet* — хуурамч мөнгө, туршилтад. **Polygon Amoy** = бидний ашиглаж буй testnet.

**EVM (Ethereum Virtual Machine):** Smart contract ажилладаг "процессор".
Ethereum, Polygon, BNB, Avalanche бүгд EVM-нийцтэй — нэг контракт бүгд дээр ажиллана.

🔗 **OneGram-той холбоос:** Бид **Polygon Amoy testnet**-ийг сонгосон — учир нь
gas үнэгүй, EVM-нийцтэй, маргааш mainnet (Polygon) руу бараг өөрчлөлтгүй
шилжинэ. [hardhat.config.js](hardhat.config.js)-д `chainId: 80002` нь Amoy.

## Модуль 5 — Smart contract ба Solidity

**Smart contract** = blockchain дээр амьдардаг програм. Нэг удаа байршуулбал
(deploy) код өөрчлөгдөшгүй, өөрөө автоматаар ажиллана. "Гэрээ"-г хүнгүйгээр гүйцэтгэнэ.

**Solidity** = EVM-ийн хамгийн түгээмэл хэл (JavaScript/C++-тэй төстэй).

Үндсэн ойлголтууд:
- `contract` — класс шиг
- `function` — метод. `view` = унших (үнэгүй), бусад = бичих (gas)
- `mapping` — key→value хадгалалт (балансууд)
- `modifier` — функцийн өмнө ажиллах шалгуур (жишээ: `onlyRole`)
- `event` — лог. Гадны систем сонсож болно

🔗 **OneGram-той холбоос:** [contracts/OneGram.sol](contracts/OneGram.sol)-ийг нээ.
`mint`, `burn`, `transfer` нь функцууд. `onlyRole(MINTER_ROLE)` нь modifier —
зөвхөн эрх бүхий хаяг л mint хийнэ.

🔬 **Дасгал:** OneGram.sol дотор `view` функц хэд байна? (Сэжүүр: `balanceOf`,
`totalSupply`.) Тэдгээр яагаад gas шаардахгүй вэ?

## Модуль 6 — Token ба стандартууд (ERC-20)

Blockchain дээрх "token" гэдэг нь smart contract дотор бичигдсэн баланс.

Стандартууд (бүгд гэрээний "интерфейс"):
- **ERC-20** — солилцоонд тэнцүү token-ууд (мөнгө, оноо, stablecoin). 1 ONEGRAM = 1 ONEGRAM.
- **ERC-721 (NFT)** — давтагдашгүй (урлаг, гэрчилгээ).
- **ERC-1155** — холимог.

ERC-20-ийн заавал байх функцууд: `totalSupply`, `balanceOf`, `transfer`,
`approve`, `transferFrom`, `allowance`. OpenZeppelin эдгээрийг бэлэн өгдөг —
бид зүгээр өвлөн авч (`is ERC20`) ашигласан.

🔗 **OneGram-той холбоос:** `contract OneGram is ERC20, ERC20Pausable,
AccessControl` — гурван бэлэн "лего" нийлүүлсэн. Бид зөвхөн `mint`/`burn`/`pause`
нэмсэн. `transfer` гэх мэт нь ERC20-оос автоматаар ирсэн.

🔬 **Дасгал:** OpenZeppelin-ийн ERC20.sol-ийг нээж (`node_modules/@openzeppelin/...`)
`_update` функцийг ол. Бид яагаад түүнийг `override` хийсэн бэ? (Сэжүүр: Pausable.)

## Модуль 7 — OneGram.sol-ийг мөр мөрөөр унших

[contracts/OneGram.sol](contracts/OneGram.sol)-ийг нээгээд:

```solidity
contract OneGram is ERC20, ERC20Pausable, AccessControl {
    bytes32 public constant MINTER_ROLE = keccak256("MINTER_ROLE");
    // ↑ "mint хийх эрх" гэсэн дүрд өвөрмөц ID

    constructor(address admin) ERC20("OneGram Gold", "ONEGRAM") {
        _grantRole(DEFAULT_ADMIN_ROLE, admin);  // admin бүх эрхтэй
        _grantRole(MINTER_ROLE, admin);          // mint хийж чадна
        ...
    }

    function mint(address to, uint256 amount) external onlyRole(MINTER_ROLE) {
        _mint(to, amount);  // шинэ token үүсгэж `to`-д өгнө
    }                       // ← QPay алт орлоо → энэ дуудагдана

    function burn(address from, uint256 amount) external onlyRole(BURNER_ROLE) {
        _burn(from, amount);  // token устгана
    }                         // ← биетээр авлаа → энэ дуудагдана
}
```

**Нягтлах гол санаа:** `mint`/`burn`-ийг зөвхөн `MINTER_ROLE`/`BURNER_ROLE`-той
хаяг хийнэ. Тэр хаяг = чиний backend. Иймээс **зөвхөн бодит алт орж/гарахад л**
supply өөрчлөгдөнө. Энэ нь Proof-of-Reserve-ийг баталгаажуулна.

🔬 **Дасгал:** Хэрэв `onlyRole(MINTER_ROLE)`-ийг устгавал юу болох вэ? (Хэн ч өөртөө
хязгааргүй алт mint хийж чадна → token үнэгүй болно. Энэ нь халдлагын гол цэг.)

## Модуль 8 — Stablecoin: юу вэ, хэрхэн гаргадаг вэ?

**Stablecoin** = тогтвортой үнэ цэнтэй token. Үнэ нь ямар нэг хөрөнгөтэй
"тогтоогдсон (pegged)" байна.

### Гурван төрөл
| Төрөл | Баталгаа | Жишээ |
|---|---|---|
| Фиат-баталгаат | Банкин дахь доллар | USDT, USDC |
| **Бараа-баталгаат** | **Агуулах дахь алт** | **ONEGRAM**, PAXG |
| Крипто-баталгаат | Илүүдэл crypto барьцаа | DAI |

### Stablecoin хэрхэн гаргадаг вэ? (5 алхам)
1. **Нөөц** — Бодит хөрөнгө (алт/доллар) аюулгүй хадгалах, аудитлуулах.
2. **Контракт** — ERC-20 + mint/burn (бид үүнийг хийсэн ✅).
3. **Mint** — Хэрэглэгч хөрөнгө оруулахад токен үүсгэх (нөөц ↑ = supply ↑).
4. **Burn** — Хэрэглэгч буцаахад токен устгах (нөөц ↓ = supply ↓).
5. **Peg барих** — `supply == нөөц` invariant-ийг үргэлж барих + Proof-of-Reserve нийтлэх.

### Peg яагаад тогтвортой байдаг вэ?
Хэрэв 1 ONEGRAM-ийн ард үргэлж 1гр алт байгаа бол, зах зээл дээр үнэ нь алтны
үнээс хазайвал арбитраж хийгчид тэгшитгэнэ. **Итгэл = нөөц бодитой байх.**

🔗 **OneGram-той холбоос:** Чиний ONEGRAM бол **алтаар баталгаажсан stablecoin**.
Бид аль хэдийн mint/burn/PoR invariant-ийг бичсэн. "1 токен = 1000₮" болговол
яг ижил кодоор **төгрөгийн stablecoin** болно — зөвхөн баталгааны хөрөнгө солигдоно.

🔬 **Дасгал:** Хэрэв чи 1000 ONEGRAM mint хийчихээд агуулахад 900гр алт л байвал
юу болох вэ? Энэ нь яагаад залилан (буюу "algorithmic depeg") болохыг тайлбарла.

## Модуль 9 — Custody ба түлхүүрийн менежмент

Хамгийн чухал, хамгийн эрсдэлтэй сэдэв. "Хэн private key-ийг барих вэ?"

| Загвар | Хэн түлхүүр барина | Давуу | Сул |
|---|---|---|---|
| **Custodial** | Платформ (чи) | UX амар, seed phrase алга | Чамд итгэх ёстой; чи hack-д өртвөл бүгд алдана |
| **Self-custody** | Хэрэглэгч өөрөө | Жинхэнэ эзэмшил | UX хүнд, алдвал тусламжгүй |
| **MPC / Smart wallet** | Хуваагдсан түлхүүр | Хоёрын дунд | Нийлмэл, үнэтэй |

**Production-ийн алтан дүрэм:** Бодит үнэ цэнтэй private key-ийг **хэзээ ч**
энгийн env хувьсагч/seed phrase дотор бүү хадга. Ашигла:
- **Cloud KMS** (Google/AWS) — түлхүүр тусгай hardware-д, гарч ирэхгүй
- **MPC** (Fireblocks, Web3Auth) — түлхүүрийг хэсэгчлэн хуваана

🔗 **OneGram-той холбоос:** [walletService.js](../functions/src/blockchain/walletService.js)
нь **зөвхөн testnet-д зориулсан** энгийн mnemonic ашигладаг. Файл дотор анхааруулга
бичсэн: mainnet-д заавал KMS/MPC руу шилжинэ.

🔬 **Дасгал:** OneGram custodial байх ёстой юу, self-custody юу? Чиний хэрэглэгчид
(голдуу энгийн иргэд) seed phrase-аа удирдаж чадах уу? Шийдвэрээ үндэслэ.

## Модуль 10 — Аюулгүй байдал ба эрсдэл

Smart contract = мөнгө барьдаг код. Алдаа = шууд алдагдал. Нийтлэг халдлагууд:

- **Reentrancy** — гадны дуудлага дундуур дахин орж мөнгө соруулах (DAO hack).
- **Access control алдаа** — `onlyRole` мартах → хэн ч mint хийнэ.
- **Integer overflow** — (Solidity 0.8+ автоматаар хамгаалдаг).
- **Oracle манипуляц** — гадны үнийн эх сурвалжийг хуурах.
- **Rug pull** — баг өөрөө нөөцийг авч зугтах (итгэлийн эрсдэл).

**Хамгаалалт:**
- OpenZeppelin шиг **аудитлагдсан** лего ашиглах (бид тийм хийсэн ✅)
- Mainnet-ийн өмнө мэргэжлийн **аудит** хийлгэх
- `pause()` зэрэг яаралтай зогсоох механизм (бид нэмсэн ✅)
- Тест бичих (бид [OneGram.test.js](test/OneGram.test.js) хийсэн ✅)

🔬 **Дасгал:** Бидний контракт дахь `pause()` ямар нөхцөлд амь аврах вэ? Нэг
бодит хувилбар бод (жишээ: backend түлхүүр алдагдсан гэж сэжиглэв).

## Модуль 11 — Stablecoin-ийг эхнээс нь гаргах (бодит замын зураг)

Бүх ойлголтыг нэгтгээд, ONEGRAM-ийг бодит токен болгох дараалал:

```
1. ХУУЛЬ      → СЗХ-той зөвшилцөх (VASP/үнэт цаас уу?). Хамгийн том блок.
2. НӨӨЦ       → Бодит алт хаана, хэн хадгалах, аудит хэн хийх.
3. КОНТРАКТ   → OneGram.sol (✅ бэлэн) → testnet → аудит → mainnet.
4. КЛЮЧ       → KMS/MPC custody (testnet-ийн mnemonic-оос шилжих).
5. RAMP       → QPay орлого → mint; татан авалт → burn (автоматжуулах).
6. PoR        → "supply == нөөц" нийтийн dashboard. Аудит тогтмол нийтлэх.
7. UX         → Flutter app дотор хэрэглэгч өөрчлөлт мэдрэхгүй (custodial).
8. (Сонголт)  → Self-custody, биржийн листинг, гадны wallet-руу гаргах.
```

**Технологи 20%, итгэл+зохицуулалт 80%.** Код хэсэг (3) аль хэдийн бэлэн.
Үлдсэн нь бизнес, хууль, аудитын ажил.
